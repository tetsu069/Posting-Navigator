# Posting Navigator v1.0.21

## v1.0.21 修正

- 3m以内の従来の条件付き救済スナップに加え、**3〜8mを第二段階で厳格判定**。
- 3m超は、両端がdegree=1の行き止まり端点・両道路がギャップ方向へ22°以内・道路軸同士25°以内の場合だけ同一道路の切れ目として救済。
- 近接並行道路、交差方向、道路外へのショートカットは接続しない。
- 独立した直線connectorは生成せず、既存OSM道路geometryの端点だけを共通nodeへ揃える方式を維持。
- Render Freeのメモリ対策として、各救済段階は候補収集後に一度だけgraphを再構築。

## v1.0.20 修正

- 1.25m固定のスナップ上限を見直し、1.25〜3.0mのギャップは**条件付き救済スナップ**で判定。
- 救済対象は異なる連結成分の近接ノードだけ。道路方向・端点次数を確認し、同じ交差点/道路接続と判断できる場合だけ結合。
- 近接する並行道路は、ギャップ方向と道路軸が一致しないため自動結合しない。
- 1.7m程度のクリップ/座標ずれは実道路の端点を共通ノードへ揃えて接続し、独立した直線コネクタは作らない。
- 3mを超えるギャップは従来どおり接続せず、エラーで停止。
- v1.0.18の共通OSM道路ネットワーク、配布対象フラグ再判定、道路外直線禁止を維持。


## v1.0.17 修正
- **配布対象道路**と**移動に使える道路**を完全に2層化。
- 配布対象は従来どおり町丁目内＋境界平行道路だけ。エリア外向き枝道を配布対象にはしない。
- 移動用ネットワークは町丁目境界の外側20mまでの実在OSM道路を保持し、分断された巡回成分の接続にだけ使用。
- Overpass取得範囲を境界外35mまで拡張し、境界直外の交差点・接続道路も取得。
- 移動区間は `posting_target=False / connector_only=True` として通常巡回と分離。
- 実道路で接続不能な場合は従来どおり偽の直線を作らずエラー停止。
- OSMキャッシュスキーマを更新し、旧キャッシュを自動破棄。
- v1.0.16までのSTRtree軽量化・Render Free向けメモリ対策を維持。

# Posting Navigator v1.0.3

町丁目KMZとOpenStreetMap道路からポスティング巡回ルートを生成し、現場ではスマホGPSで配布済み区間を自動記録するWeb/PWAです。GitHub Pagesを画面、RenderをPython APIとして利用できます。



## v1.0.5で追加・修正

- 通常の地図クリックでは開始地点を変更しない。`地図で開始地点を指定` を押した後の1クリックだけを開始地点として採用。
- ルート生成後は自動で現場モードへ切り替えず、「ルート作成」画面に最適巡回順を表示。
- 巡回順を **1 → 2 → 3 → ...** の全区間リストとして表示。前へ／次へ、または項目クリックで順番を追える。
- 選択中の区間だけ青く太く強調し、次の区間を水色点線で予告。全体の赤線との役割を分離。
- 矢印は全道路へ大量表示せず、選択中区間の道路形状上だけに表示。道路の局所接線から方位を計算する。
- ナビ区間生成時、離れた道路形状を誤って1本のLineStringで直結しない連続性チェックを追加。斜めの偽ルート／誤矢印を防止。
- 現場モードでも全区間に矢印をばら撒かず、「次に進む未完了区間」だけを青く強調して矢印表示。

## v1.0.3 で追加・修正

- 道路網を単に色塗りする方式から、**巡回順序付きステップ列**へ変更
- Chinese Postman方式で対象道路をできるだけ一筆書きに近く巡回
- 小さな非連結道路成分を最大成分から落とさず、全成分を巡回対象に保持
- 各巡回ステップに `seq`（順番）・道路種別・OSM ID・重複通行情報を保持
- 地図上に進行方向の矢印 `→` を約45m間隔で表示
- 巡回順番号を10ステップごとに表示し、START / GOALも表示
- 通常巡回=赤、必要な重複通行=橙、非連結道路への移動=灰色点線で区別
- 現場モードにも担当ルートの進行方向矢印を表示
- メトリクスに対象道路本数・非連結成分数・移動区間距離を追加
- v1.0.2のOverpass複数ミラー・User-Agent対応、町丁目境界/薄色表示を維持
- GitHub Pages公開用Render URLを `docs/config.js` に保持

## v1.0で追加

- PWA対応（ホーム画面へ追加、アプリ風全画面表示）
- スマホGPS追跡
- 担当ルートの未配布=赤 / 配布済み=緑表示
- GPS位置がルートから指定距離内に入ると区間を自動完了
- 端末LocalStorageへ進捗保存
- 6桁共有コードによる複数端末参加
- 担当者別進捗をAPIへ保存し約5秒ごとに同期
- Google Identity Servicesログイン（任意設定）
- Googleログイン利用時、自分が作成した共有プロジェクト一覧を表示
- 従来のKML/KMZ/GeoJSON/CSV出力を維持

## ローカル起動

Windowsは `start_web.bat` をダブルクリックします。ブラウザで `http://127.0.0.1:8787` が開きます。

手動の場合：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -e .
posting-navigator-web
```

## 公開構成

```text
GitHub Pages (docs/)
        |
        | HTTPS API
        v
Render (posting_navigator.webapp)
        |
        +-- Overpass / OSM
        +-- SQLite progress DB
```

### 1. RenderへAPIを公開

1. GitHubへこのリポジトリをpush。
2. Render → New → Blueprint → このリポジトリを選択。
3. `render.yaml` を適用。
4. デプロイ後のURL（例 `https://posting-navigator-api.onrender.com`）を控える。
5. `/api/health` を開き、`"version":"1.0.3"` を確認。

Renderの環境変数：

- `ALLOWED_ORIGINS`: `https://あなたのGitHubユーザー名.github.io`
- `GPS_THRESHOLD_M`: 初期の自動完了判定距離。既定18m
- `SYNC_INTERVAL_MS`: チーム同期間隔。既定5000ms
- `GOOGLE_CLIENT_ID`: Googleログインを使う場合のみ設定
- `POSTING_NAV_DB`: SQLite DBパス

### 2. GitHub PagesをAPIへ接続

`docs/config.js` を編集します。

```js
window.POSTING_NAVIGATOR_API = 'https://実際のAPI名.onrender.com';
```

GitHub → Settings → Pages → Source を **GitHub Actions** にします。`.github/workflows/pages.yml` が `docs/` を公開します。

### 3. PWAをスマホへ追加

Android/Chromeではページを開き「アプリをインストール」または「ホーム画面に追加」。iPhone/Safariでは共有ボタン → 「ホーム画面に追加」です。GPS利用にはHTTPSが必要なので、公開運用ではGitHub PagesのHTTPS URLを使ってください。

## Googleログイン設定（任意）

1. Google Cloud ConsoleでOAuth 2.0 **Web application** のClient IDを作成。
2. Authorized JavaScript originsへGitHub Pagesのオリジンを追加。
   - 例: `https://YOUR-GITHUB-USER.github.io`
3. Renderの `GOOGLE_CLIENT_ID` にClient IDを設定。
4. Renderを再デプロイ。

Googleログインなしでも、共有コードと進捗同期は利用できます。ログインを使うと「自分が作ったプロジェクト一覧」を呼び戻せます。

## 現場での使い方

1. 「ルート作成」でKMZ → 町丁目 → 人数を指定し、巡回ルートを生成。
2. 自動的に共有コードが発行される。
3. 各担当端末は共有コードで参加し、「現場モード」で自分の担当を選択。
4. 「GPS開始」。ルートから設定距離内を通ると、該当区間が赤から緑へ変化。
5. 「チーム」タブで全担当の進捗を確認。

GPS誤差や並行道路が近接する場所では誤判定の可能性があります。現場では判定距離を8〜40mで調整できます。

## データ永続化について

進捗は端末のLocalStorageにも保存されるため、同じ端末ではブラウザ再読み込み後も復元できます。API側はSQLiteです。Renderの一時ディスクだけで運用するとサービス再起動・再デプロイでDBが消える可能性があります。本番で履歴を永続保存する場合は、Render Persistent Diskを `/var/data` などにマウントし、`POSTING_NAV_DB=/var/data/posting_navigator.db` に変更してください（利用プランの条件を確認してください）。将来PostgreSQL等へ置換できるようAPI層を分離しています。

## 既存CLI

```bash
posting-navigator build \
  --kmz data/input/shinjuku_posting_map.kmz \
  --area 北新宿一丁目 \
  --output output/kita-shinjuku-1 \
  --start-lon 139.6925 \
  --start-lat 35.7005 \
  --workers 4
```

実OSM以外を許可しない場合は `--no-offline-fallback` を追加します。実運用時は `summary.json` の `data_mode` が `osm` であることを確認してください。

## v1.0.8 追加・修正

- GPS追跡中、現在のナビ区間を順方向に自動で進めるターンバイターン更新を追加。
- GPS完了判定を「全未配布道路から最近傍」ではなく、現在の巡回順付近の区間を優先する方式に変更し、隣接道路の誤完了を抑制。
- 町丁目境界から最大約8mの道路中心線も巡回候補に含め、境界道路の取りこぼしを軽減（`BOUNDARY_ROAD_BUFFER_M` で変更可能）。
- KMZ description の `世帯数` を読み取り、左カラムに町丁目の総世帯数を表示。
- 現場モードに「推定配布済み世帯数」「推定残り世帯数」を追加。GPS巡回距離の進捗率から按分する参考値。

## v1.0.10 担当エリア自動分割
- 担当人数が2人以上の場合、完成済みの全体ルートを単純に切るのではなく、町丁目ポリゴンを道路負荷を基準に地理的に連続した担当エリアへ分割します。
- 各担当エリアごとに独立した Chinese Postman 巡回ルートを生成します。
- 地図では担当エリアと担当ルートを色分けし、担当者をクリックするとそのルートだけ強調します。
- KMZの町丁目世帯数がある場合、対象道路量を基準に担当別の推定世帯数を配分します。
- 現場モードでは選択した担当者専用の案内ステップとGPS進捗を利用します。


## v1.0.11 道路外直線の完全禁止

- 担当エリア分割で生じた非連結道路成分の間を、座標の直線で結ぶ処理を廃止。
- 成分間の移動は町丁目全体のOSM道路グラフ上の最短経路だけを使用。
- transfer区間もOSM道路geometryをそのまま描画。
- 実道路上で接続不能な場合は偽ルートを描かず生成エラー。
- 出力前にstep間の連続性を検証し、不連続ならLineString化を拒否。

## v1.0.12 住宅優先・公園園路抑制

- Overpass取得に建物、公園・緑地、学校等の面情報を追加。
- 道路ごとに住宅近接度（residential_score）を算出。
- 公園・学校・緑地内で住宅から離れた footway/path/pedestrian 等は配布対象から除外。
- 除外道路も必要な接続用 connector として保持するため、住宅への唯一アクセスを壊しにくい。
- 公園内道路や非住宅道路を重複通行に使うコストを大幅に引き上げ、何度も横切るルートを抑制。
- 地図/KMLの「対象道路」には配布対象道路だけを表示。



## v1.0.14 Render Free向けメモリ最適化

- 建物・公園等の文脈判定を `unary_union` 総当たり方式から Shapely `STRtree` 空間インデックス方式へ変更。
- 各道路では50m以内の候補建物だけを検索し、住宅近接度・25mコリドー建物面積を計算。
- 公園・学校・緑地も道路と交差し得る候補だけを検索して非住宅重複率を計算。
- 全建物を巨大MultiPolygonへ統合しないため、Render Free (512MB) でのピークメモリを大幅に抑制。
- 住宅密度スコアの意味と公園内道路抑制の判定基準はv1.0.13から維持。

## v1.0.13 KMZ/町丁目状態同期の修正

- ルート生成時に、ブラウザが保持しているKMZファイル本体を `/api/build` へ再送信します。
- 生成ボタン押下時に画面上の町丁目選択値を直接読み取り、サーバー側の一時アップロード状態に依存しません。
- Renderの再起動・一時ファイル消失が `/api/areas` と `/api/build` の間に起きても、ルート生成を継続できます。
- KMZ読込時は先頭の町丁目を明示的に選択し、内部状態と画面表示の不一致を防ぎます。
- multipart送信時の `offline_fallback=0` が誤ってTrue扱いになる問題も修正しました。
