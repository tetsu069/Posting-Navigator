# Posting Navigator v1.1.5 — OSMオフラインキャッシュ強化版

1町丁目を1本の巡回ルートとして生成するポスティングナビです。ルーティングはv1.1.3の現場優先方式を維持し、v1.1.5ではOverpass障害時でも運用しやすいようOSMデータ取得を二重キャッシュ化しました。

## v1.1.5 の主な変更

- **低メモリ奇数頂点ペアリング**: 奇数交差点が多い場合はNetworkXのBlossom完全マッチングを使わず、Dijkstra結果を1組ずつ破棄する近傍ペアリングへ切替。Render Free 512MBでのSIGKILLを防ぎます。
- 奇数頂点が24以下の小規模ケースでは従来の厳密最小重みマッチングを維持します。

- 通常の「巡回ルートを生成」は、保存済みOSMキャッシュがあればOverpassへアクセスせず即利用。
- ルート生成に成功したOSMデータをブラウザのIndexedDBへ自動保存。
- Render再起動・再デプロイでサーバー側一時キャッシュが消えても、同じ端末ならブラウザ保存データを自動復元。
- 「OSMデータを更新して再生成」ボタンを追加。これを押した時だけ最新Overpass取得を試す。
- 最新取得が失敗しても既存キャッシュがあればルート生成を継続し、`osm-cache-fallback` として表示。
- Render側にも町丁目別キャッシュを保持し、同一プロセス中の再計算では再取得しない。
- キャッシュ状態を「この端末に保存済み／Renderに一時保存済み／初回取得が必要」で表示。

## 実運用

1. ある町丁目で一度OSM取得に成功させる。
2. 以後、同じ端末では通常のルート生成時にOverpassを呼ばない。
3. 道路データを更新したい時だけ「OSMデータを更新して再生成」を押す。
4. 更新時にOverpassが落ちていても、保存済みデータがある場合は古いキャッシュで継続できる。

注意: ブラウザキャッシュは端末・ブラウザごとです。別端末では最初の取得が必要です。ただしPCでルートを作成して共有プロジェクトにした後、スマホは生成済みルートを開くだけならOSM再取得は不要です。
